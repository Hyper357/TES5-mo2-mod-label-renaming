# 安全与恢复

## 变更前

- 关闭 Mod Organizer、SkyrimSE、Skyrim Launcher。
- 确认 `ModsPath`、`ProfilePath` 是目标实例，不是另一个 profile。
- 先运行盘点和预览，不直接编辑 live 文件。
- 检查新名称冲突、非法字符和当前条目存在性。

## 应用范围

应用脚本只允许：

- 改目标 MOD 文件夹名；
- 改 `ProfilePath/modlist.txt` 中对应的名称。

应用脚本必须只读并校验 `plugins.txt`、`loadorder.txt`，不能把它们作为写入目标。排序和 `+`/`-` 状态保持原样。

不允许：

- 删除 MOD 文件夹或覆盖已有目标文件夹；
- 修改 ESP/ESM/ESL/BSA/BA2；
- 重新生成排序；
- 自动启用或禁用条目；
- 把整个 Skyrim 安装目录提交到 GitHub。

## 备份内容

一次应用至少备份：

- 每个目标文件夹的 manifest（文件数、总大小），写为 `folder-manifest-before.csv`；
- `modlist.txt`；
- `plugins.txt` 和 `loadorder.txt` 的基线副本；
- 预览表和实际 rename map；
- 文件数量、大小；需要严格验证时再计算 SHA-256。

默认不复制 MOD 文件夹内容——改名只改变文件夹名和 `modlist.txt` 对应行，文件内容不变，因此 manifest 足够回滚和验收。如果确实需要内容级备份（例如担心目标文件夹被覆盖），显式传 `-CopyFolders`，此时每个目标文件夹全量复制到备份目录的 `mods\` 下，`Verify-RenameMap.ps1` 会自动改用逐文件对比，`Restore-RenameBackup.ps1` 也会自动切换为从备份复制恢复。

备份应放在仓库外的本地路径，不要提交到 GitHub。

## 回滚原则

回滚优先是可恢复的移动和复制：

1. manifest 模式（默认）：将当前新文件夹改回旧名（文件内容未变，无需复制）；`-CopyFolders` 模式：将当前新文件夹移入备份目录中的 quarantine，再从备份恢复旧名称文件夹；
2. 恢复 `modlist.txt`；
3. 默认不恢复 `plugins.txt` / `loadorder.txt`，避免覆盖备份之后用户做的其他合法改动。

应用失败时脚本会尝试自动回滚，并保留备份路径供人工处理。

## 路径隔离（由 2026-09-23 事故确立）

**背景**：某次为一个"入库后自动改名并排序"的 Python 工具做端到端验证时，测试通过 `DS_ROOT` 环境变量指向临时沙箱目录，沙箱内的改名与 `modlist.txt` 写入都正确落位。**但该工具生成的「回滚脚本」模板里，`modlist.txt` 路径被硬编码成了真实安装路径**。测试在沙箱里执行回滚，结果把备份复制回了真实 `modlist.txt`，用 9 行测试夹具覆盖了 2239 行的真实文件。

沙箱隔离了脚本自身的行为，**隔离不了模板里的字符串字面量**。

### 强制约定

1. **模板里不得出现任何绝对安装路径。** 生成脚本时，`modlist.txt` / `mods` / profile 路径一律由调用方传入的根目录变量插值产生。
2. **沙箱测试必须断言"真实文件零变化"**：测试开始前读取真实目标文件的字节，结束后再读一次，`assert before == after`。这条断言比任何语法检查都直接。
3. **写文件一律干跑默认**，必须显式 `--apply` 才落盘。
4. **写入前自动备份 + 写入后断言**：行数、关键段落逐行比对、无 BOM、CRLF 计数。

### 恢复方法（本次验证有效，可复用）

1. 枚举全盘所有 `modlist` 命名的快照——**包括 zip 内部**，解析每份的行数、条目数、BOM、CRLF 与关键标记串，按标记匹配数 → 行数排序。
2. 优先检查 `.claude/backups/`，自动化快照与人工快照常在那里，容易被只盯着 `tools/renaming_backups/` 的清单漏掉。
3. **闭合账目**：基线与损坏状态的行数差额，必须能由一份明确的「新增清单 + 删除清单」完全解释。对不上就说明某个前提是错的，**此时不要写入**。
4. **逐行锚定**：用损坏前捕获的原文（读取记录、grep 输出）逐行断言重建文件的首段、分区边界与末段。**行数吻合不等于正确，逐行吻合才作数。**
5. 文件夹已消失的条目，MO2 保存时会自行删除；有文件夹无条目的模组，MO2 会显示为未归类。两者都会自愈，**但优先级位次不会自愈**——那才是真正要保住的东西。

## 并发会话

同一工作区可能有多个 agent 会话并行。写入 `modlist.txt` 这类全局状态文件前：

- 确认没有其它会话正在作业（检查近期修改的文件、工作日志）；
- 写入后记录并公布最终校验值（行数 / 字节 / sha1），让其它会话能判断自己看到的是哪一版。
