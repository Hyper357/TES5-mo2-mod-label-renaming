# 命名与标签标准

当前版本：**2.0**（2026-09-23）。1.x 格式见文末「历史格式」。

## 推荐格式

```text
[母体作者] 中文功能名 - 变体/层级 (by 补丁作者) — Official English Title — 【标签】 【标签】
```

三段结构，缺一段就省略那段，不要留空占位：

| 段 | 内容 | 必需 |
|---|---|---|
| 1 | 中文段：`[母体作者]` + 中文功能名 + ` - 变体/层级` + ` (by 补丁作者)` | 功能名必需，其余可选 |
| 2 | 官方英文标题（Nexus 标题原文） | 建议保留 |
| 3 | 标签池，`【分类·子类】` | 必需，至少一个 |

## 作者位：母体前缀 vs 补丁后置

**中括号前缀永远属于原作者母体**，它同时承担"在 MO2 左栏把同作者条目聚成一簇"的排序职责。

```text
[4thUnknown] 伊斯拉米尔护甲 - 基础本体 — Ysmir Armor SE — 【服装·护甲】 【本体·ESP】
[4thUnknown] 伊斯拉米尔护甲 - SPID独立分发补丁 (by Leo) — SPID - Ysmir Armor — 【系统·分发】 【补丁·SPID】
```

- `[4thUnknown]` 是护甲原作者 → 占前缀，两条自然聚拢。
- `Leo` 只是补丁作者 → 后置为 `(by Leo)`，**不得喧宾夺主占据前缀**。
- 补丁条目仍然跟随母体作者聚簇，而不是散到"Leo"名下——这是前缀规则的主要目的。

作者确实无法作为母体前缀时（多人协作、来源本地、作者不明），才回落到标签池：`【作者·xxx】`。

## 变体与层级

同一母体下常有多条，用 ` - ` 分隔的变体词标明层级关系，让 MO2 里同名母体的条目自上而下读得通：

| 变体词 | 含义 |
|---|---|
| `本体` | 基础本体（Base Mod / ESP） |
| `材质` | 材质与 PBR 贴图替换层 |
| `物理` | 3BA / HIMBO / SMP 物理网格层 |
| `分发` | SPID / KID / DAV 等运行时分发层 |
| `补丁` | 兼容性或修复补丁 |
| `预设` | 配置 / INI / BodySlide 预设 |

变体词不是标签的重复。`【本体·ESP】` 标技术形态，` - 本体` 标它在母体家族里的层级位次，两者都留。

## 分隔符与间距

- **禁用密集点号 `·` 作为名称主体的分隔符**。中文名 + 英文名 + 多个 `【】` 标签已经很长，再塞点号会形成密集堆叠，读起来疲劳且难以扫读。名称主体一律用带空格的短横线 ` - `。
- **点号只允许出现在标签内部**：`【服装·护甲】`、`【体型·3BA】`。这是唯一例外。
- **中段统一用 ` — `**（em dash，两侧各一个半角空格），不用 `-` 或 `–`。工具脚本按 ` — ` 切分英文标题。
- **标签之间留一个半角空格**：`【服装·护甲】 【体型·3BA】`，不要写成 `【服装·护甲】【体型·3BA】`。多个黑色粗括号紧挨同样造成视觉疲劳。

## 中文名判断

中文名只翻译功能，不翻译品牌。示例：

| 英文词 | 推荐 | 备注 |
|---|---|---|
| Overhaul | 大修 | 对整体系统或地点重做时使用 |
| Rework / Remade / Redone | 重制 | 对模型、地点或系统重新制作 |
| Replacer | 替换 | 纯替换内容，不夸大为大修 |
| Fix | 修复 | 修复问题或兼容性 |
| Patch | 补丁 | 两个 MOD 的兼容连接 |
| Framework | 框架 | 为其他 MOD 提供 API 或运行基础 |
| Addon / Expansion | 扩展 | 增加主 MOD 的内容或功能 |
| Distribution | 分发 | SPID 等运行时分配 |
| Plugin | 插件 | 只有需要强调技术形态时使用 |

作者名、正式品牌名、系列品牌保留原文，不音译。`SKSE`、`SPID`、`OAR`、`MCO`、`3BA`、`CBBE`、`HIMBO`、`SMP`、`AE`、`SE`、`VR`、`NG`、`PBR`、`BOS`、`KID` 等缩写同样保留。

## 标签原则

至少考虑以下维度：

- 功能：材质、动画、任务、战斗、服装·护甲、地点、视觉效果等；
- 技术：SKSE、框架、MCM、引擎、SPID、OAR 等；
- 平台：AE、SE、VR、NG；
- 体型：3BA、CBBE、HIMBO、UBE、多体型等；
- 作者与系列：前缀已承载作者时不要重复加 `【作者·】`；系列只在证据充分时添加。

标签应该精确而不是堆砌。一个纯 DDS 材质附加组件通常需要 `【材质·PBR】`、`【材质·替换】` 和对象类别，不需要 `【技术·SKSE】`。

## 系列判定

以下证据可以支持"同系列"：

1. 标题共享明确产品品牌；
2. 页面说明明确写明 series、family、part 或 addon 关系；
3. Nexus 合集或依赖关系明确连接；
4. 作者在页面中说明属于同一产品线。

以下情况不能单独证明同系列：

- 只是同一个作者；
- 都含有 `PBR`、`BOS`、`NG` 等技术词；
- 都是同一类型 MOD；
- 中文译名看起来相似。

## 置信度

- 高：官方标题、页面用途和系列关系均有一手来源支持。
- 中：功能明确，但系列或变体仍需人工确认。
- 低：只能从名称或本地文件推测，必须保留待核状态。

## 历史格式（1.x）

```text
作者或系列锚点·中文功能名·变体 — Official English Title — 【标签】【标签】
```

与 2.0 的差异：

| | 1.x | 2.0 |
|---|---|---|
| 名称主体分隔 | 密集点号 `·` | ` - ` |
| 作者位置 | 名称首位（与系列锚点争位）或末尾 `【作者·】` | 名称最前 `[作者]`，系列下沉到标签 |
| 标签间距 | `】【` 紧挨 | `】 【` 留空 |

**存量名称不为格式而重命名。** 只为统一格式去改几千个文件夹名，收益（视觉一致性）远低于风险（每次改名都要动 `modlist.txt` 与备份链）。规则是：**在因其它原因触碰某条目时，顺带把它升级到 2.0**。

## 排序不在本标准的范围

本文件只定义名称。MO2 左栏的优先级排序、变体层级的前后关系、空 Mod 垫片，是**显式启用的扩展**，见 `sorting-and-spacers.md`。默认流程不改排序、不改启用状态、不动 `plugins.txt` / `loadorder.txt`。
