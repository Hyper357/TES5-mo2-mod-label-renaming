# 命名与标签标准

## 推荐格式

```text
作者或系列锚点·中文功能名·变体 — Official English Title — 【标签】【标签】
```

不是每一条都必须有作者/系列锚点。锚点的目的，是让 MO2 名称排序具备可读性；标签的目的，是让人可以筛选和复核。

## 中文名判断

中文名只翻译功能，不翻译品牌。示例：

| 英文词 | 推荐 | 备注 |
|---|---|---|
| Overhaul | 大修 | 对整体系统或地点重做时使用 |
| Rework / Remade / Redone | 重制 | 对模型、地点或系统重新制作 |
| Replacer | 替换 | 纯替换内容，不夸大为大修 |
| Fix | 修复 | 修复问题或兼容性 |
| Patch | 补丁 | 两个 MOD 的兼容连接 |
| Framework | 框架 | 为其他 MOD 提供 API 或运行基础 |
| Addon / Expansion | 扩展 | 增加主 MOD 的内容或功能 |
| Distribution | 分发 | SPID 等运行时分配 |
| Plugin | 插件 | 只有需要强调技术形态时使用 |

## 标签原则

至少考虑以下维度：

- 功能：材质、动画、任务、战斗、装备、地点、视觉效果等；
- 技术：SKSE、框架、MCM、引擎、SPID、OAR 等；
- 平台：AE、SE、VR、NG；
- 作者：同作者条目较多且有筛选价值时添加；
- 系列：只有正式品牌或页面关系明确时添加。

标签应该精确而不是堆砌。一个纯 DDS 材质附加组件通常需要 `材质·PBR`、`材质·替换` 和对象类别，不需要添加 `技术·SKSE`。

## 系列判定

以下证据可以支持“同系列”：

1. 标题共享明确产品品牌；
2. 页面说明明确写明 series、family、part 或 addon 关系；
3. Nexus 合集或依赖关系明确连接；
4. 作者在页面中说明属于同一产品线。

以下情况不能单独证明同系列：

- 只是同一个作者；
- 都含有 `PBR`、`BOS`、`NG` 等技术词；
- 都是同一类型 MOD；
- 中文译名看起来相似。

## 置信度

- 高：官方标题、页面用途和系列关系均有一手来源支持。
- 中：功能明确，但系列或变体仍需人工确认。
- 低：只能从名称或本地文件推测，必须保留待核状态。
