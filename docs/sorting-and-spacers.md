# 排序层级与样式一空 Mod 垫片（显式启用的扩展）

> 本文件描述的是**超出上游默认边界**的部分。默认流程只改名称，不改排序。
> 只有当请求里明确要求"整理某个分区""理顺排序"时，才启用本文件的规则。

---

## 一、前置认知：MO2 左栏的方向

**MO2 左栏自上而下 = 优先级由低到高，向下赢得最终胜出权。** 也就是列表越靠下、越晚加载、越覆盖上面的。

对应的 `modlist.txt` 内部是**完全倒序**：

> `modlist.txt` **第一行 = MO2 界面最底部 = 最高优先级**；文件最后一行 = 界面最顶部 = 最低优先级。

这一点极易记反，且**所有写入 `modlist.txt` 的脚本都按此方向处理**。副作用：`wc -l` 得到的行数等于真实行数（MO2 写文件时带尾随换行）。

实例：`-99 工具生成输出（务必置底）_separator`、`-00 核心运行库、SKSE、引擎修复与通用前置_separator`
这类名字里写着"置底/核心"的分隔符，在 `modlist.txt` 里分别位于文件头部与尾部——名字描述的是**界面上**的位置，不是文件里的位置。

## 二、样式一空 Mod 垫片

分区内部、各大作者组或功能组之间，用一个**普通空 Mod 文件夹**充当微型视觉垫片：

```text
----------- [4thUnknown] 经典重甲系列 -----------
```

要点：

- **必须在 MO2 中表现为「可勾选的普通条目」**。做法：建一个文件夹，里面只放一个基础 `meta.ini`（`[General]` + `gameName=SkyrimSE`），再在 `modlist.txt` 中加一行 `+该名称`。
- **严禁**使用带 `_separator` 后缀的系统大分隔符来充当垫片。`_separator` 是另一个层级的工具（分区级），两者不要混用。
- 文件夹名**严禁** Windows 非法字符：`/` `\` `:` `*` `?` `"` `<` `>` `|`。需要时转义为 `&` 或 `-`。
- 为什么用空 Mod 而不是 `_separator`：空 Mod 只是个名字，不引入任何层级语义；分区级 `_separator` 一旦挪动就会打乱整个分区边界。用前者做组间呼吸，边界仍然由后者独占。

## 三、微排序覆盖铁律

### 服装护甲类

左栏自上而下的层级顺序（下方胜出）：

```text
Tier 1  基础本体（Base Mod / ESP）
   ↓
Tier 2  材质 / PBR 贴图替换（覆盖本体原贴图）
   ↓
Tier 3A 3BA / HIMBO / SMP 物理网格（覆盖静态网格）
   ↓
Tier 3B SPID 分发与地面修复补丁（最终胜出）
```

### 动画战斗类

```text
Tier 1  基础框架本体
   ↓
Tier 2  AE Support / 引擎 Bug 修复补丁
   ↓
Tier 3  扩展招式包与条件 OAR 树
   ↓
Tier 4  第一人称专用动画（置底胜出，绝不被三人称动作冲乱视角）
```

两条共同的判断依据：**谁修改的文件更"靠后于渲染管线"，谁就该排在下面**。贴图覆盖本体、网格覆盖贴图、分发补丁决定哪套网格被真正挂上去；第一人称动画必须压过任何三人称招式包，否则视角会被冲乱。

## 四、执行要求（启用本扩展时）

1. **确认 MO2 / SkyrimSE / Launcher 全部退出**。MO2 运行中向磁盘写 `modlist.txt`，关闭时会被内存缓存回写覆盖。
2. **备份 `modlist.txt`、`plugins.txt`、`loadorder.txt`**，带时间戳。
3. **生成专属可逆回滚脚本**（Python 或语法验证过的 `.ps1`），并同步生成操作清单 JSON。
4. 写入 `modlist.txt` 必须 **UTF-8 无 BOM + CRLF**，不得破坏总行数与 `+` / `-` 前缀语义。
5. **干跑默认**：脚本不带 `--apply` 时只报告不落盘。
6. 写后校验：无 BOM、CRLF 计数、总行数、以及**逐行断言关键锚点位置**。
7. **路径隔离**：任何在沙箱/临时目录里跑的验证，其生成的回滚脚本也必须从沙箱根派生路径。见 `safety-and-recovery.md`。

## 五、与纯重命名批次的关系

| | 纯重命名批次 | 分区整理（本扩展） |
|---|---|---|
| 改动对象 | 文件夹名 + `modlist.txt` 对应条目的名称 | 文件夹名 + `modlist.txt` 的**顺序** |
| 是否动排序 | 否 | 是（核心目的） |
| 是否动启用状态 | 否 | 一般否；仅隔离误入条目时临时置为禁用 |
| 建议批次大小 | 一批一个分区或一个作者家族 | **一次只做一个分区** |

两件事不要塞进同一次操作。重命名批次的意义是"名称变、行为不变"，一旦掺进排序，出问题时无法判断是名字还是顺序导致的。

## 六、误入条目处理

分区里出现明显不属于该分区的条目时，不要直接删。做法：

1. 打上归属标签，例如 `【待移出·非服装】`；
2. 在 `modlist.txt` 中把它们**归拢到该分区的临时隔离区**（分区底部一段），而不是原地留着打散分区结构；
3. 等真正归属的分区做到时再迁移。

直接删会连带丢掉它在 `modlist.txt` 里的优先级位次，而位次无法从 `mods/` 目录反推恢复。
